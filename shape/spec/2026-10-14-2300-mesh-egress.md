# 2026-10-14 23:00 — Mesh egress

The owner's provider (Infisical), git host and other upstreams sit on a private mesh. Until now
every farmy container reached the internet directly and the mesh not at all. This record adds one
optional container that joins the mesh and lets everything farmy starts reach mesh hosts through
it. It is a proxy, nothing more: no internal network, no exit node, no subnet router. The later
record "egress control" makes the proxy the only way out, with an allowlist; this one is built so
that is additive.

## The model

- **One container, `farmy-egress`**, on the `farmy` network, never published, running `tailscaled`
  in userspace-networking mode (no TUN device, no `NET_ADMIN`, works on Docker Desktop), exposing
  a SOCKS5 and an HTTP CONNECT proxy on port 1055 to the farmy network only. Its state lives on
  the volume `farmy-egress` (at `/var/lib/tailscale`), so registration happens once per machine.
- **Every container farmy starts** (keys, knowledge, app, the fragment's services) and every
  process farmy runs for the secrets (the provider) get `HTTP_PROXY`, `HTTPS_PROXY`,
  `ALL_PROXY` pointing at it, in both cases, and `NO_PROXY` for localhost, `host.docker.internal`,
  the compose project's own names and farmy's shared containers. The Infisical CLI, curl, package
  managers and the broker's upstreams reach mesh hosts; MagicDNS names resolve on the mesh
  (`socks5h`). The control container's own shell does not get them: the shim starts it before
  farmy.yml is read; what farmy runs does.
- **Git over SSH** in app containers goes through the SOCKS proxy: the toolbox installs
  `netcat-openbsd`, the entrypoint sets `core.sshCommand` with a `ProxyCommand nc -X 5 -x
  farmy-egress:1055 %h %p` when `ALL_PROXY` is set.
- **Joining.** `egress.authkey` names an unlocking value (listed under `secrets.unlock`, obtained
  by the shim: Keychain, secret-tool, command or prompt), not a provider secret: the provider is
  behind the mesh, so the node is up before any provider runs. Order at start: unlock values →
  egress → provider → brokers. With the key the node joins by itself. Without, farmy starts the
  container, reads the registration URL from its log, prints it once with the instruction to
  register the node on the control server, and waits up to `egress.join_timeout` (default 10m).
  On timeout start goes on: services that need no mesh still work; status shows the node as
  unregistered with the URL, and a service whose clone then fails says the mesh is unregistered.
- **`egress.tailscale.login_server`** is a URL (Headscale); omitted for Tailscale's own.
- **Status.** `farmy status --json` gets a top-level `egress` (null without `egress:`): state
  (`registered`, `unregistered`, `stopped`), the mesh name and address, the registration URL when
  unregistered, the proxy address. `status` prints an `egress` line first; the TUI shows it.
- **Without `egress:`** nothing changes anywhere. `stop` with no name stops the node too;
  `destroy` never removes its volume.
- **The key** is in no file, no docker command line and no inspect output: it reaches the node
  through an exec's stdin.

## FORMATS.md

## Tests altered

None. The existing tests run without `egress:` and must see nothing of it.

## Scenario list

egress_test.rb
- with an authkey from the shim the egress node joins by itself and nothing is printed to register
- the authkey is in no file, no docker command line and no inspect output, and reaches the node on stdin
- without an authkey the registration URL from the node's log is printed once, with the instruction to register, and start goes on after join_timeout
- a node registered before, its state on farmy-egress, joins again at the next start without printing anything
- status --json shows the egress node with its mesh name and address, and status prints its line
- status --json shows an unregistered node with its registration URL
- every container farmy starts gets the proxy variables pointing at the egress node, and NO_PROXY for the local names
- the egress node is on the farmy network, publishes nothing and keeps its state on the farmy-egress volume
- the egress node is up before the provider is asked for anything, and the provider runs with the proxy variables
- the toolbox installs netcat-openbsd and the app container gets the socks address, for git over SSH through the proxy
- a login server of your own is given to the node
- an authkey that is not under secrets.unlock is refused, naming both
- without egress nothing is set and no egress container runs
- stop with no name stops the egress node too, and destroy keeps its volume

broker_test.rb
- with HTTP_PROXY set the broker sends its upstream requests through the proxy

integration_test.rb
- the egress node runs and its proxy port answers from another farmy container
- git in the app container reaches SSH hosts through the proxy: core.sshCommand uses nc -X 5

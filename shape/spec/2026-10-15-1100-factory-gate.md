## Decided

**D1. The gate runs on an export of the commit.** The test container mounts the run volume read-only at
`/workspace` and gets a tmpfs at `/scratch` that allows executables (`--tmpfs /scratch:exec`). Its command
exports the commit into `/scratch/tree` (`git -C /workspace archive HEAD | tar -x -C /scratch/tree`), goes
there (or to the definition's `workdir` inside it) and runs the test command; `HOME` and `TMPDIR` are
folders under `/scratch`. The suite may write into its tree (Rails' `log/`, `tmp/`); all of it is gone
with the container. This is also the literal "tests exactly the commit": what is not committed is not
there, ignored files included (dependencies kept in the tree, such as `node_modules`, are not; those kept
in the definition's `mounts:` are). Supersedes the read-only tree of 10:00 (choice 4).

**D2. The gate reaches the service's sidecars, and nothing else.** By default each run makes an internal
network `<name>-run-<id>-gate` (`docker network create --internal`: no route out), attaches the service's
fragment containers to it under their compose service names (`docker network connect --alias postgres
<network> shop-pg`) for as long as the run lasts, and runs every gate on it alone. A Rails suite reaches its
own test database on the service's Postgres by name, as in development; the gate has no internet, no
egress proxy, no broker (the app container and `<name>-keys` are never attached). `factory.gate.network:
none` runs the gate with `--network none` and attaches nothing. The agent's container is never on the
gate's network. At the end of the run (any end, cancel included) the sidecars are detached and the network
removed. A sidecar that is not running is left out, with a note in the run's git log. Supersedes choices 5
and 6.

**D3. `farmy factory prune [--older-than <n>d|h|m]`** removes the run volumes of finished runs (phase
`done`), all of them, or those that ended longer ago than the limit; it prints each volume it removed and
leaves the runs' folders (state and logs) in place. Runs in progress are never touched. `farmy factory show`
prints the run volume and its size (`volume  <name>-run-<id>  <size>`, measured with `du -sh` in a short
container labelled `farmy.role=measure`), or `volume  <name>-run-<id>  removed (farmy factory prune)`.

**D4. Git through the mesh.** Git containers get the proxy variables (as every container farmy starts) and,
with an SSH route, an ssh command that goes through the proxy like the app container's:
`core.sshCommand` = `ssh -o StrictHostKeyChecking=accept-new -o ProxyCommand='nc -X 5 -x <proxy> %h %p'`
with the mesh, `nc -X connect -x <host:port>` with `egress: {proxy: …}`, plain ssh without egress. A push over
an SSH route through the mesh then takes the same way as the clone.

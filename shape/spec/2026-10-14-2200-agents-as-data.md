# 2026-10-14 22:00 — Agents as data

Claude Code was wired into farmy by hand: the toolbox installed it by name, the entrypoint linked
`~/.claude`, wrote its hooks and knew `CLAUDE_CONFIG_DIR`, `farmy.yml` had a `claude:` key with a
mode and a token name, the status read one `agent.status` on a volume called `<name>-claude`, and
`docker top` was searched for `claude` or `codex`. Codex had half of that. Every further agent
would have meant another special case in five places. This record turns an agent into a record
of fields that farmy reads, ships a catalogue of six, and lets the owner add or override entries
in `farmy.yml`. Claude is one catalogue entry and a special case nowhere.

## The model

An **agent entry** has these fields (FORMATS.md, "Agents"):

- `install`: a shell line run as root while the toolbox builds, on an apt or an apk base; a string
  for both, or `{apt:, apk:}` when they differ, null for a base the vendor does not support.
- `login`: a path under `$HOME`, or a list of them, holding the login; linked into
  `farmy-shared/<name>/` so that one login serves every container.
- `state`: paths under the first login path that are per service (transcripts, sessions), kept
  on the service's `<name>-agents` volume under `<agent>/` and linked from the login path.
- `headless_login`: the command that logs in without a browser; `farmy agents` prints it.
- `token_env`: optional; the provider's secret of that name goes into the app container's
  environment under that name. The one documented exception to "no secret in a container".
- `env`: optional plain variables the agent needs in the container.
- `api`: optional; `key`, `base_url` (the variables the agent reads) and `upstream` (the route
  with that upstream serves it), for api-key mode through the broker.
- `mcp_add`: optional; run once per login by the entrypoint, with `FARMY_MCP_URL`.
- `status_hooks`: optional; `file` under `$HOME` and `events` (event → state) written by the
  entrypoint in the `{"hooks": {"<Event>": [{"hooks": [{"type": "command", …}]}]}}` shape that
  Claude Code, Codex and Gemini CLI share.
- `process`: optional; what `docker top` shows while the agent runs. Default: the name.
- `mode`: `subscription` (default) | `api-key` | `off`, the default for every service.

`farmy.yml` `agents:` is a map name → fields (a catalogue name with `{}` takes the entry as it is,
with some fields overrides those and keeps the rest; a new name is an agent of your own). The list
form stays accepted as a shorthand. The `claude:` key is gone: refused, pointing at `agents`. A
definition's `agents: {claude: api-key}` sets a mode per agent for that service (the old
`claude: api-key` goes). The modes, now per agent: `subscription` links the login and gives the
token when `token_env` and the secret exist, and keeps the agent's `api` variables out;
`api-key` gives `<base_url var>=http://keys:9181/<route>` and `<key var>=via-farmy-keys` from the
route whose upstream is the agent's, and is refused when there is no such route; `off` leaves the
agent out of that service's image.

**The seams.** The app image's build context holds `agents.tsv` (one line per agent on for the
service: name, install per base, login, state, mcp_add, hooks file and events, process); the build
argument `AGENTS` and the container's `FARMY_AGENTS` name the same agents. The toolbox installs
from the file; the entrypoint links, registers the MCP and writes the hooks from it. The status
file is `/home/dev/.farmy-service/<agent>/agent.status`; `farmy status --json` reports `agents`,
one entry per agent, from its hooks' file or its process. The per-service volume `<name>-claude`
becomes `<name>-agents` at `/home/dev/.farmy-service`. `CLAUDE_CONFIG_DIR` is no longer set (its
value was Claude's default).

## The catalogue, as verified on 2026-10-14

Every field was checked against the vendor's current page; the worker writes `agents.yml` from
this table and cites these URLs above each entry. A field the page does not state is null.

- **claude** — install: apt `curl -fsSL https://downloads.claude.ai/keys/claude-code.asc -o
  /etc/apt/keyrings/claude-code.asc && echo "deb [signed-by=/etc/apt/keyrings/claude-code.asc]
  https://downloads.claude.ai/claude-code/apt/stable stable main" > /etc/apt/sources.list.d/claude-code.list
  && apt-get update && apt-get install -y claude-code`; apk `wget -O /etc/apk/keys/claude-code.rsa.pub
  https://downloads.claude.ai/keys/claude-code.rsa.pub && echo https://downloads.claude.ai/claude-code/apk/stable
  >> /etc/apk/repositories && apk add claude-code` (https://code.claude.com/docs/en/setup).
  login: `.claude`, `.claude.json` (https://code.claude.com/docs/en/authentication#credential-management,
  https://code.claude.com/docs/en/claude-directory). state: `projects`. headless_login:
  `claude setup-token` (https://code.claude.com/docs/en/authentication#generate-a-long-lived-token).
  token_env: `CLAUDE_CODE_OAUTH_TOKEN` (https://code.claude.com/docs/en/authentication#authentication-precedence).
  api: `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`, `https://api.anthropic.com`
  (https://code.claude.com/docs/en/llm-gateway-connect). mcp_add: `claude mcp add --transport http

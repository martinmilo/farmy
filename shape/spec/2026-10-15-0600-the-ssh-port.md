# 2026-10-15 06:00 — The SSH port

The owner ran record 3000: start loaded the broker before the clone and the key was in the agent,
but the clone failed. The route's upstream was `ssh://git@git.example.com:2222`, the repository
`https://git.example.com/acme/shop.git`; the entrypoint cloned `ssh://git@git.example.com/acme/shop.git`
and the egress node dialled port 22, where only 2222 is open.

## Decided

- **The rewritten clone URL carries the upstream's user and port**:
  `ssh://<user or git>@<host>[:<port>]/<path>`, the port only when the upstream names one.
- **An insteadOf rule for later fetches and pushes**: the app container gets `DEV_GIT_SSH_ROUTES`,
  space-separated `https://<host>/=ssh://<user>@<host>[:<port>]/` pairs, one per granted SSH git
  route, and the entrypoint turns each into `url.<ssh URL>.insteadOf <https URL>`, so a remote or a
  submodule named by its https URL goes over SSH, on the route's port, as the clone did.

## Tests altered

`keys_test.rb`, "with an SSH git route for its host an https repo: is cloned over SSH, and nothing
is rewritten" becomes "… is cloned over SSH, without an http rewrite, and with an insteadOf rule":
it still refutes `DEV_GIT_ROUTES`, and asserts the new `DEV_GIT_SSH_ROUTES`.

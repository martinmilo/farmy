# No token in any file farmy writes

Found while shaping 2026-10-19-0840: in subscription and token mode `.work/<name>/compose.yml`, which farmy
writes for the app container, held the agent's `token_env` secret in plain text, although FORMATS says
"farmy never stores a secret on disk".

Decided (the owner, 2026-10-19), before 0.1.1:

- No secret's value is in any file farmy writes: nothing under `.work/`, nor `.env` in the containers
  folder.
- `compose.yml` names the variable only: `environment: [NAME]` or `NAME: ${NAME}`. farmy gives the value in
  the environment of the `docker compose` process at every compose up that makes or recreates the app
  container, from the provider (run again, as every load does) or the held unlocking values.
- The app container still gets the variable, after `farmy start`, after `farmy restart` without values
  given again, and after `farmy stop` then `farmy start`, whose fast path reuses the existing compose file
  (a read-only work-side helper found that path reuses the file as written and asks the provider nothing;
  with the value gone from the file it must now supply it too).

Left out: Docker's own record of a container's environment (`docker inspect`), which the documented
exception accepts.

## Scenarios (SecretsOffDiskTest)

1. In subscription mode no file farmy writes holds the provider's token, and the app container still has it.
2. The app's compose file names the token's variable without its value.
3. After farmy restart the app container still gets the provider's token.
4. A token from an unlocking value stays out of every file farmy writes, and after farmy restart without the
   value given again the app container still gets it from the held values.
5. After farmy stop and farmy start, which reuses the app's compose file, the app container still gets the
   provider's token.

# A killed run's egress gate goes with its orphaned agent

The login turn record (2026-10-19-0907) removes an orphaned login-mode agent container before the next run
on that login starts its agent. The worker noted that the dead run's filtering gate
(`<name>-run-<id>-egress-gate`) stayed running after its agent was removed.

Decided (the owner, 2026-10-19), before 0.1.1:

- When a run removes an orphaned agent container, it also removes that orphan's run's egress gate, if it
  is there.
- Each `orphans_stopped` entry records it: `{"container", "run", "gate"}`, `gate` the gate's container
  name, or null when there was none. `factory show` names the gate on the orphan's line.

The existing scenario 2 of FactoryLoginOrphansTest changes meaning: it now also expects the gate removed
and recorded.

Left out: the dead run's networks and volume (the run volume is kept after a run anyway).

## Scenario (FactoryLoginOrphansTest, changed)

2. A controller killed mid-turn leaves its agent running, and the next run on that login stops the orphan
   and its run's egress gate before its own agent starts and records both.

# farmy 0.1.1

Factory runs now leave a full record, can work on a subscription login of their own (Codex first), and
keep secrets off command lines and out of the files farmy writes.

## Install

- The README now leads with a one-line install from the latest release (`curl -fsSL …/releases/latest/download/install | sh`),
  followed by the checksum-verified download for macOS and Linux.
- A release's installer installs the release it came from (`--to` still picks another). When its bin
  folder is not on your `PATH`, it ends by printing the `export PATH=…` line to add.

## Factory

- **Run record.** Each iteration keeps `iteration-<i>.agent.json` (the exact `docker run`, the
  environment with secrets shown as `<NAME>`, the image and its id, the exit code, start and end times),
  the prompt it was given, and the agent's stdout and stderr apart. Stdout is where usage reports land
  (Claude's `--output-format json`, Codex's `--json`). Each run keeps the agent entry it used
  (`agent_config`) and its CLI version (`agent_version`).
- **Agent versions.** Agent entries take a `version:` command, filled in for every catalogue agent. It
  runs once per run, without a network, and gets 30 s; a CLI that does not answer in time is recorded as
  `unknown` and the run goes on. A version command that fails is recorded as `unknown` too, with its exit
  code and the last line it wrote to stderr (`exited 126: sh: 1: codex: Permission denied`).
- **Agents run as dev.** The catalogue installs Codex and Cursor outside any home directory, owned by root
  and runnable by every user: Codex was linked from `/usr/local/bin` into root's home, so dev could not
  run it (and `farmy factory login <service> codex` failed). Codex is pinned to 0.163.0. Once the agents
  are installed, the toolbox build runs each agent's `version` line as dev and fails, naming the agent,
  when dev cannot run it. Each check gets 30 s, and install lines download their installer to a file before running it.
- **Factory logins.** An agent entry can declare `factory_login: {path, create}`. `farmy factory login
  <service> <agent>` makes a login volume of that agent's own, and profiles with `mode: login` mount it.
  The interactive shared login is never used. Codex is the first catalogue agent with one (`codex login
  --device-auth`; device-code login must be enabled in your ChatGPT security settings).
- **One agent per login at a time.** Iterations on the same factory login take turns (phase
  `login_wait`). If a run's controller dies mid-turn, the next run on that login removes the orphaned
  agent container and that run's egress gate before its own agent starts, and records it in
  `orphans_stopped`. If the orphan cannot be removed after several tries, the run ends `login_blocked`
  instead of starting a second agent on the same login.
- **Pinning.** `docs/factory.md` shows how to pin an agent's model, reasoning effort and CLI version
  through its entry in `farmy.yml`, with Codex and Claude Code examples.

## Secrets

- During a factory run no secret's value is on any `docker` command line: tokens reach the agent
  container as `-e NAME`, the value only in that `docker` call's environment.
- An agent's token is no longer written into `.work/<service>/compose.yml`: the file names the variable,
  and farmy supplies the value when it brings the container up (`start`, `restart`, `rebuild`). A
  compose file from 0.1.0 that still holds a token is rewritten on the next start.

## Publishing

- Publication keeps the README's `releases/latest/download/…` links as written; versioned links still
  name the published release.

## Known limitations

- Editor dev containers started from `.work/<service>/.devcontainer` no longer get the Claude token,
  since the compose file no longer holds it. Start the service through farmy instead.
